# 帰り道ナビ / station-route-app

日本大学文理学部から桜上水駅・下高井戸駅へ歩き、目的駅への到着を比べる静的Webアプリです。
出発地と比較駅は固定です。目的駅・徒歩時間・出発日時を変更できます。

## 使い方

1. Netlifyの公開環境またはNetlify Devでアプリを開き、目的駅と両駅への徒歩時間を入力します。
2. 「最適な駅を検索」を押します。構内移動も徒歩時間に含めます。
3. 日時を変更すると固定日時で検証できます。「現在時刻に戻す」で秒更新に戻ります。
4. メニューから時刻表の編集、徒歩計測、履歴の個別削除、バックアップを利用できます。
5. 検索結果の下からも「徒歩計測を開始」「停止して保存」を操作できます。推奨駅を初期選択し、開始前に変更できます。

## 推奨ルール

- 下り方面：桜上水駅だけを検索し、候補がある場合に推奨します。
- 上り方面で両駅の最適候補が各駅停車：下高井戸駅を推奨します。
- その他の上り：予測到着が早い駅を選び、同着なら両駅を表示します。

指定ルールによる推奨が到着比較では遅くなる場合、その差も正しく表示します。
最初の便だけでなく、2時間以内に発車する後発先着、次発、乗り逃し後の最早到着も比較します。
通常より最大5分短い徒歩時間で乗れ、通常の検索結果より早く着く場合だけ短縮案を表示します。
大学の出発期限と電車の発車時刻を、現在日時との差から毎秒更新します。

## 時刻表・到着予測

桜上水・下高井戸の上下線、平日・土曜・日曜の12表・2,330件を自動読み込みします。
発車・種別・行先の原文を保持します。next_day=true は前運行日の24時以降として扱います。
日曜と土曜は元JSONでは同内容ですが、別々に編集できます。祝日は日曜を手動指定してください。

駅すぱあとAPIの平均路線名を取得し、路線を固定した平均待ち時間探索の乗車時間を発車に加算します。
待ち時間や徒歩時間を重複加算しません。既存の駅間平均JSONも保持しています。
APIキーはNetlify Functionsの環境変数 `EKISPERT_API_KEY` で管理します。ブラウザには渡しません。
登録後はFunctionsスコープとデプロイコンテキストを確認し、再デプロイしてください。[設定・認証確認手順](API_INTEGRATION.md)
キー未設定・取得失敗時に到着を補いません。登録済みの到着時刻は優先します。

下り略称の対応表は api-config.js にあります。「高八」「セ橋」は種別変更駅で区間を分割します。
終点を越える便や別支線の便、通過が登録された駅、APIで対応する平均路線を取得できない候補は予測に採用しません。
APIにより確認するのは平均路線の停車パターンであり、当日の各列車の運行変更を取得する機能ではありません。
各停表記のないAPI路線は、区間の全途中駅数とAPIの停車駅数を照合してから使用します。推定した到着は「推定到着」と表示します。
元JSONの平日には、京王八王子行き（八・高八）が16:16の次は20:18になっています。18:00〜20:00には直通候補がなく、到着や推奨を補いません。乗換経路は今回追加していません。

## 編集・保存・徒歩計測

時刻表の追加・編集・削除、一括登録、初期化、JSONバックアップを維持しています。
駅別時刻は「駅名,到着,発車,停車または通過」。翌日は24:05と入力します。
編集内容を別保存し、初期JSONを直接変更しません。保存キー・形式は従来のv1を維持します。
更新後の初回読み込みでは他駅の時刻表と廃止した設定を整理し、両駅の登録・編集・削除を引き継ぎます。

徒歩計測対象は2駅だけです。履歴に駅・時間・日時を表示し、個別に削除できます。
結果画面とメニューは1つの計測状態を共有します。開始日時と対象駅をlocalStorageへ保存し、日時差で経過を求めるため、バックグラウンド復帰・リロード・再起動後も復元します（同じブラウザ・保存データ保持が前提）。
画面更新用のタイマーが止まっても計測時間には影響しません。停止日時との差を履歴へ保存します。従来どおり保存範囲は1秒〜120分です。
平均は履歴から再計算します。「平均を適用」後は記録の追加・削除を入力値にも反映します。
適用中の最後の記録を削除すると、初期値（桜上水9分・下高井戸8分）へ戻ります。
以前の他駅への徒歩記録はバックアップ内に保持しますが、画面と平均計算には使用しません。

## 開発・検証

画面はHTML/CSS/JavaScript、API接続はNetlify Functionsです。jsdomは開発テスト専用です。

~~~text
npm ci
npm test
npm run build
~~~

ビルドは静的ファイルを dist/ に用意し、Netlifyは `netlify.toml` に従ってFunctionsを別途バンドルします。push・公開は行いません。
`netlify dev` でローカル確認できます。公開環境では「保存・バックアップ → API接続確認」から両APIの認証を確認できます。
実ブラウザの描画、実APIの認証・登録ドメイン制限・実データによる検証は未実施です。
