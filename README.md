# 帰り道ナビ / station-route-app

出発地から各駅までの徒歩時間と電車を比べる静的Webアプリです。
初期データは自動で読み込みます。通常の検索にファイル登録、APIキー、インストールは不要です。

## 使い方

1. `index.html` をブラウザで開き、出発地・目的地を指定します。
2. 比較する2駅と、それぞれの徒歩時間を入力します。構内移動も含めた時間です。
3. 「最適な駅を検索」を押します。現在日時は秒単位で更新します。
4. 日時を編集すると固定したテスト日時で試せます。「現在時刻に戻す」で戻ります。
5. 「駅ごとの比較・乗り逃した場合」を開くと、次発と到着差も確認できます。

曜日は土日を自動で土休日にします。祝日は「曜日を指定する」で土休日を選択してください。
出発地は表示名です。徒歩時間は手入力または保存した計測平均を使います。

## 使用する時刻表

モード選択や確認操作はありません。利用者の編集、提供JSON、その他の駅の仮ダイヤを自動で扱います。

- 桜上水・下高井戸・笹塚の京王線上り：提供6表、計1,328件をそのまま使用します。
- **提供JSONには到着時刻がありません。** この範囲では走行時間を補完せず、発車候補とカウントダウンを表示します。到着が未登録の場合は最適駅を断定しません。
- その他の駅・方向：列車単位で生成した各駅停車の仮ダイヤを使用し、「シミュレーション」と表示します。
- 目的駅への到着時刻が分かる候補では、後発先着・同着も含めて比較します。

京王線、高尾線、相模原線、京王新線の全52駅を選択できます。
路線をまたぐ場合は乗換も探索します。仮ダイヤの未提供区間は3分、停車は30秒、乗換余裕は1分の仮定です。実際の運行を再現したものではありません。
笹塚から京王新線へ向かう便は、本線の提供表とは別のシミュレーションです。

## メニュー内の機能

- **徒歩時間を計測**：全駅の計測・保存・平均の適用。平均は分単位で切り上げます。
- **時刻表を編集**：追加・編集・削除、一括登録、初期化。変更はすぐ検索に反映します。
- **保存・バックアップ**：localStorageに自動保存。必要に応じてJSON保存・確認後の復元ができます。

駅別時刻の入力形式は、1行に `駅名,到着,発車,停車または通過` です。
翌日の00:05は24:05と入力します。不明な到着は空欄のまま保存できます。
通過駅で乗降はできません。不正な時刻・重複・時系列の逆転を検証します。

元JSONは変更せず、追加・更新・削除だけを別保存します。保存キーと形式は以前のバージョンと同じです。
旧モードや確認情報は互換性のため保持しますが、検索可否には使用しません。

## 動作確認例

出発日時を2026-10-19 18:00:00、比較駅を明大前・代田橋、目的駅を笹塚にします。

- 徒歩を両方0分にすると、同じ列車を使う同着を確認できます。
- 明大前0分・代田橋120分では明大前、逆にすると代田橋を選びます。
- 比較駅を高尾山口・橋本、目的駅を新宿にすると、乗換のあるシミュレーションを確認できます。
- 初期の桜上水・下高井戸→笹塚では、元データの発車候補と「到着未登録」を確認できます。

## 開発・検証

公開アプリはHTML/CSS/JavaScriptのみです。jsdomは開発テスト専用です。

```text
npm ci
npm test
npm run build
```

検証環境はNode.js 24.21.0です。`npm run build` は元JSONのバンドルを生成し、静的9ファイルを `dist/` にコピーします。
GitHubへのpush、Netlifyへの公開・設定変更は今回行っていません。

主なファイル：

- `index.html` / `style.css`：検索画面とメニュー
- `script.js`：徒歩・最早到着比較・秒更新・表示
- `railway-core.js`：JSON変換、列車生成、接続検索、保存形式
- `data-manager.js`：編集・保存・計測と画面の接続
- `data/`：元JSON2ファイル、バンドル、件数・ハッシュ
- `tests/`：既存回帰・データ・DOM統合テスト

今回の変更と検証の詳細は [UI_SIMPLIFICATION_REPORT.md](UI_SIMPLIFICATION_REPORT.md) に記載しています。
